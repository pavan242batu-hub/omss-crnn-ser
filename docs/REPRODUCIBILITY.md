# Reproducibility and verification status

This document describes the portable feature-extraction and training
workflow, the checks completed during repository preparation, and the
limitations of those checks.

The verified implementation uses convolutional layers followed by a
bidirectional GRU. The checks below do not establish that every historical
manuscript result was produced by these exact files and settings.

## Repository entry points

- `scripts/extract_features.py`: extract MFCC features from supplied
  noisy or already-enhanced OMSS audio.
- `scripts/models.py`: preserved model definitions.
- `scripts/training_core.py`: preserved fold-training helpers.
- `scripts/train_fold.py`: input validation and optional training of
  one model configuration on one outer fold.

Feature extraction does not perform OMSS enhancement.

The training entry point does not launch training unless `--train`
is explicitly supplied.

## Tested environment

The model and training smoke tests ran with:

- Python 3.13.16
- TensorFlow 2.21.0
- Keras 3.13.2

These identify the tested environment, not a complete dependency lockfile.
Other dependency versions and hardware details were not captured in the
verification record summarized here.

## Required inputs

Users must supply:

1. A manifest containing `FileName` and `OriginalID`.
2. The corresponding noisy and already-enhanced OMSS audio.
3. An assignment CSV containing `OriginalID`, `y`, and `fold`.
4. Feature caches generated by the portable extractor.

The training wrapper requires metadata-bearing caches with these keys:

- `X`
- `filenames`
- `original_ids`
- `metadata_json`

It checks feature shape, dtype, finite values, condition metadata, frame
count, filename order, and original-ID order against the supplied manifest.

Cache metadata checks establish alignment, not independent verification
of audio provenance or enhancement history.

## Generate 400-frame feature caches

Run these commands from the repository root, replacing the example paths
with your actual input and output paths.

```bash
python scripts/extract_features.py \
  --manifest /path/to/omss_grouped_manifest.csv \
  --audio-root /path/to/noisy \
  --condition noisy \
  --frames 400 \
  --output /path/to/mfcc_noisy_T400.npz
```

```bash
python scripts/extract_features.py \
  --manifest /path/to/omss_grouped_manifest.csv \
  --audio-root /path/to/omss \
  --condition omss \
  --frames 400 \
  --output /path/to/mfcc_omss_T400.npz
```

Supply the corresponding audio root for each condition. Both extractions
must use the same manifest and row order.

## Validate a fold without training

```bash
python scripts/train_fold.py \
  --manifest /path/to/omss_grouped_manifest.csv \
  --assignments /path/to/cv_fold_assignment.csv \
  --noisy-cache /path/to/mfcc_noisy_T400.npz \
  --omss-cache /path/to/mfcc_omss_T400.npz \
  --name fusion_guided \
  --fold 0 \
  --frames 400
```

Without `--train`, the wrapper validates inputs and reconstructs the split.
It does not build a model, launch training, or write output files.

## Run a one-epoch training smoke test

```bash
python scripts/train_fold.py \
  --manifest /path/to/omss_grouped_manifest.csv \
  --assignments /path/to/cv_fold_assignment.csv \
  --noisy-cache /path/to/mfcc_noisy_T400.npz \
  --omss-cache /path/to/mfcc_omss_T400.npz \
  --name fusion_guided \
  --fold 0 \
  --frames 400 \
  --seed 42 \
  --epochs 1 \
  --patience 15 \
  --out-dir /path/to/new_smoke_test_directory \
  --train
```

The output directory must not already exist.

One epoch checks execution; it is not an evaluation of converged model
performance.

The historical defaults are 60 maximum epochs and early-stopping patience
15. A full run using those defaults has not been verified by the checks
documented here.

## Configuration names

| Name | Input and pooling/attention |
|---|---|
| `noisy_gap` | Noisy single stream; global average pooling |
| `noisy_att` | Noisy single stream; temporal attention |
| `omss_gap` | OMSS single stream; global average pooling |
| `omss_att` | OMSS single stream; temporal attention |
| `fusion_gap` | Noisy/OMSS fusion; global average pooling |
| `fusion_att` | Fusion; GuidedAttention with cue disabled |
| `fusion_guided` | Fusion; GuidedAttention with cue enabled |

These names define the portable interface. They are not independently
recovered evidence of historical experiment-launch names.

Fusion channel order is noisy first, OMSS second.

## Preserved training procedure

- Outer test folds and numeric labels come from the assignment CSV.
- Remaining original IDs are split using the first split of a four-way
  StratifiedGroupKFold with shuffle enabled and random_state=42.
- The validation-split seed remains 42 even when the training seed changes.
- Class weights are calculated from training rows.
- Optimizer: Adam with learning rate 0.001.
- Loss: four-class categorical cross-entropy with label smoothing 0.1.
- Training batch size: 32.
- Validation selection metric: macro recall over labels 0, 1, 2, and 3.
- Learning-rate reduction: factor 0.5, patience 5, monitoring val_uar.
- Early stopping: monitors val_uar and restores best weights.
- No additional feature normalization is performed inside run_fold.

## Split and metric limitations

No OriginalID overlaps were found between training, validation, and test
within any of the five supplied outer folds.

This verifies separation by the supplied OriginalID. It does not establish
speaker-independent evaluation.

Neutral is absent from:

- Test partitions in outer folds 0 and 1.
- Validation partitions in outer folds 1, 2, 3, and 4.

The historical metric is:

```python
recall_score(
    y_true,
    y_pred,
    average="macro",
    labels=range(4),
    zero_division=0,
)
```

An absent true class therefore contributes zero to the four-class average.
The affected partitions have a maximum possible reported UAR of 0.75,
even with perfect classification of every available example.

These assignments and metric semantics are preserved for historical
comparability. Changing them defines a different evaluation protocol.

A mean of fold-level UAR values is not generally interchangeable with
UAR calculated from pooled out-of-fold predictions.

## Training outputs and limitations

A successful training invocation writes:

- `run_config.json`
- `run_result.json`
- A prediction archive, for example `cv_fusion_guided_f0.npz`

The prediction archive contains probabilities, numeric labels,
original IDs, and the number of completed epochs.

The preserved training core does not save model weights or the full
epoch-by-epoch training history.

Its prediction filenames do not encode every training setting. The wrapper
requires a fresh output directory to avoid collisions and stale-run skips.

The preserved prediction writer may store original IDs as an object array.
Loading that field can require allow_pickle=True. Do this only for trusted
archives, never arbitrary downloaded files.

## Observed TensorFlow diagnostic

The successful one-epoch run emitted a layout-optimizer diagnostic involving
stateless dropout and an NHWC-to-NCHW transpose:

```text
layout failed: INVALID_ARGUMENT:
Size of values 0 does not match size of permutation 4
```

Training nevertheless completed and the saved-output checks passed.

No model definitions or optimizer settings were changed to suppress the
message. Its performance or numerical implications were not independently
evaluated.

## Not yet established

The completed checks do not establish:

- Historical OMSS-generation provenance.
- Historical experiment-launch names, seeds, or complete run schedules.
- Speaker-independent evaluation.
- Training success for every configuration and fold.
- Multi-epoch callback behavior.
- Model serialization and reload.
- Full cross-validation performance.
- Exact reproduction of manuscript results.
- Identical results across environments or hardware.

Do not commit private audio, feature caches, or smoke-test predictions to
the repository.
